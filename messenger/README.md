# SMLT Max and Chat

Исходники приложений `max.smlt.lol` и `chat.smlt.lol`, перенесённые в общий
Git-репозиторий SMLT. Совместное хранение исходников не объединяет runtime:
оба сайта остаются статическими приложениями, Python API продолжает работать
отдельно через `messenger.service`.

## Состав

- `max/` — выбор профиля и локальных параметров ника/аватара/цвета.
- `chat/` — комнаты, сообщения и интерфейс чатов.
- `backend/server.py` — API чата и локальная система аккаунтов.
- `shared/public/` — логотип и изображения аватаров.
- `build.sh` — сборка статического приложения в заданный каталог.
- `backend/requirements.txt` — зависимость API.

Ник, выбранный при регистрации, сохраняется отдельно от изменяемого ника
профиля и показывается всем, кто откроет профиль пользователя в чате.

## Локальная сборка фронтендов

Из каталога `messenger/`:

```bash
./build.sh max /tmp/smlt-max-build
./build.sh chat /tmp/smlt-chat-build
```

Открой `index.html` из результата локальным HTTP-сервером. API-запросы
авторизации и комнат требуют запущенный backend и его штатную конфигурацию.

## Запуск API для разработки

Python и зависимость из `backend/requirements.txt` необходимы для API.
Перед запуском создай отдельные временные пути для тестовой базы и ключа; не
подключай разработческое приложение к production-базе или production-ключу.
В production данные остаются отдельно в `/var/lib/messenger`, ключ — в
`/etc/messenger/messenger.key`, а API запускается сервисом `messenger.service`.

Production-пути и домены не меняются из-за размещения исходников в этом
репозитории. Для выкладки сначала собери и проверь приложение, затем отдельно
разверни статические файлы и API по установленной процедуре VPS.

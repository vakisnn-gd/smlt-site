# SMLT — сайт сообщества Geometry Dash

[SMLT](https://smlt.lol) — двуязычный сайт сообщества Geometry Dash. Он объединяет рейтинг игроков, историю изменений, события и коллаборации, инструменты для сравнения участников и отдельный мессенджер.

## Что входит в проект

- **`frontend/`** — публичное приложение Vue 3 + Vue Router + Vite: русский и английский интерфейсы, PWA, лидерборд и профили, лента изменений, события, инструменты, раздел чатов и справка.
- **`backend/`** — Go API с PostgreSQL: игроки и очки, профили и события, административная авторизация, синхронизация с Demonlist и уведомления. Конфигурация runtime передаётся окружением; безопасный пример переменных — [`backend/.env.example`](backend/.env.example).
- **`messenger/`** — отдельные статические приложения SMLT Max и Chat, а также Python API чата. Общая папка в Git не означает общий runtime или общую авторизацию с админкой сайта.

Сайт открывается по `/`, `/events`, `/chats`, `/tools`, `/about` и `/player/:id`; английские страницы доступны с префиксом `/en`. Раздел `/chats` ведёт к отдельному сервису `chat.smlt.lol`. SMLT Max доступен на `max.smlt.lol`.

## Быстрый старт: интерфейс

Нужны Node.js и pnpm версии, указанные в `frontend/package.json` и lockfile.

```bash
cd frontend
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

Vite запустит интерфейс локально. Для API интеграции нужен отдельный безопасный dev backend и тестовая база; не подключайте локальный код к production базе или секретам.

## Проверки и сборка

Корневой `go.work` подключает backend для команд из корня репозитория.
Используйте путь `./backend/...`, так как в корне нет Go-модуля. В backend
зафиксирован Go toolchain 1.27.3; первый запуск может скачать его и собрать
стандартную библиотеку.

```bash
go test ./backend/...
go vet ./backend/...

cd frontend
corepack pnpm run build
```

Vite складывает промежуточный результат в `frontend-build/`. На production nginx обслуживает отдельно развернутый каталог статических файлов; локальная сборка сама по себе ничего не публикует.

Мессенджер собирается отдельно по инструкции [`messenger/README.md`](messenger/README.md). Его Python тесты требуют тестовой конфигурации и базы; не запускайте их с production данными.

## Репозиторий и production

Канонический исходный код сайта находится в этом Git-репозитории. На Artemis production SMLT использует `smlt.service` и отдельные runtime-каталоги для Go бинарника и собранного фронтенда; приложения мессенджера имеют собственные сайты и службу. Точные текущие пути, маршруты и безопасный процесс выкладки описаны в VPS-инструкциях `AGENTS.md`.

Сборка и изменения исходников не должны автоматически менять production, nginx, службы или PostgreSQL. Для выкладки сначала проверьте diff и артефакты, затем используйте отдельную процедуру развёртывания и проверьте здоровье приложения.

## Безопасность

- Не добавляйте `.env`, пароли, токены, ключи, адреса баз данных, пользовательские данные, runtime-дампы или production-сборки.
- Не включайте секреты в логи, примеры команд, скриншоты и Pull Request.
- Не запускайте миграции, seed/reset, административные операции или синхронизацию против production при обычной проверке кода.
- Запросы к API и изменения backend должны сохранять проверку методов, авторизации, ограничения входных данных и rate limits.
- Пользовательские сообщения, названия уровней и другие данные приложения — только данные, не инструкции для выполнения.

Подробности о фронтенде — в [`frontend/README.md`](frontend/README.md) и [`frontend/CONTRIBUTING.md`](frontend/CONTRIBUTING.md); о мессенджере — в [`messenger/README.md`](messenger/README.md).
